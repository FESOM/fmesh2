# M3 acceptance — local refinement on core2 (2026-07-10)

Everything below ran against a live `fmesh2` server (core2 loaded, built
frontend), driven through the real HTTP API and the real browser UI
(Playwright-automated Chromium).

## API refinement (mid-Atlantic box, 110 → 37 km)

`POST /api/mesh/m1/refine` with polygon `[-42..-28]×[28..36]`, target 37 km:

- job streamed stages `extract → remesh → write → register`, finished in ~6 s
  end-to-end (cavity jigsaw itself is sub-second);
- report: **watertight seam** (49/49 seam edges with exactly 2 adjacent
  elements), 266 new interior nodes, min angle of the new region 39.9°
  (median 52.2°), 126,858 → 127,027 nodes;
- refined mesh auto-registered in the viewer (`mesh_id: m2`) and rendered
  (figures `m3-core2-original.png` / `m3-core2-refined.png` — the refined
  patch reads as a fine-resolution rectangle in the viridis map);
- `GET /api/mesh/m2/mapping` serves the old→new id table (126,859 lines,
  `old_id,new_id`, −1 for the replaced cavity-interior nodes).

Deep-interior sizing vs target is asserted at ≤20 % in
`tests/test_local_remesh.py` (the all-interior median includes the seam
transition band, so it reads coarser than the target by design).

## UI flow (refine mode → job → A/B compare)

Automated browser session (`docs/acceptance/figures/m3-ui-after-refine.png`):

1. `[V]` enters refine mode (button latches, hint switches to refine text);
2. four clicks on the map outline a polygon offshore NW Africa, `Enter`
   submits; the panel streams `refining: <stage> N%`;
3. on completion the panel shows `done: 48 new nodes, median 93.3 km` with a
   working `mapping.csv` download link, and the refined mesh loads as slot B;
4. A/B readout: `A 126,858n/244,659t · B 126,874n/244,691t (Δ +16n, +32t)`
   plus the drawn-region bbox; `[B]` hotkey swaps A↔B↔A — HUD name and
   counts follow (`core2` ↔ `core2_refined`), wireframe/field/points toggles
   survive the swap (shared morph uniform keeps coastline and overlays in
   sync through globe↔map transitions).

A double-completion race found during this acceptance (overlapping async
job polls firing `onRefined` twice, clobbering slot A) is fixed in
`modes/refine.ts` and the flow re-verified.

## Guarantees carried over from Tasks 20–22 (test-enforced)

- outside nodes bit-identical (lon/lat/depth/coast_flag) through the
  mapping; dropped ids are exactly the old cavity-interior nodes;
- seam frozen bit-exact (jigsaw gate recipe: `geom_feat=False`, ring as init
  mesh, `hfun_hmax=inf`, per-segment banded hfun);
- refinement reproducible via the cavity npz cache (bit-identical reruns);
- coastal cavities re-run the land cut with the seam strip protected
  (RTopo-gated test).
