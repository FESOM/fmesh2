# fmesh2 — visual jigsaw-based mesh generator for FESOM2

## Overview

`fmesh2` is the successor to `fmesh`: a locally-installed tool (`pip/conda install`, `fmesh2` CLI opens a browser UI) for building, inspecting, and editing FESOM2 ocean meshes. It keeps jigsaw as the meshing engine but replaces the Google-Earth-KML + ParaView workflow with an interactive WebGL viewer that handles NG5-scale meshes (7.4M nodes / 14.7M triangles) at 60fps.

Key capabilities, in delivery order:
1. **M1 Viewer** — open any FESOM2 mesh, explore it on a 3D globe or Plate Carrée map with wireframe/scalar overlays, coastline, node inspection.
2. **M2 Generation** — resolution-field layer stack (base/mercator, coastline distance, bathymetry, drawn polygons, imported lon/lat fields) with live preview and node estimate; jigsaw + vectorized post-processing; reproducible headless builds from `project.yaml`.
3. **M3 Local refinement** — re-mesh only inside a drawn polygon of an existing mesh; outside geometry stays bit-identical.
4. **M4 Node editing** — select/drag/smooth nodes with quality safeguards and a journaled undo/redo that keeps hand-edits reproducible.

All architecture and UX decisions were validated in a brainstorm with a working render spike (2026-07-10); do not re-litigate them.

FESOM2 mesh format (confirmed against both meshes):
- `nod2d.out`: count line, then `id lon lat flag` (1-based ids, flag 1 = boundary/coast)
- `elem2d.out`: count line, then three 1-based node ids per triangle
- `aux3d.out`: `nlev` line, `nlev` level depths (negative down), then one bottom depth per node (positive)

## Testing Strategy

- **Unit tests (pytest)**: core I/O (core2 roundtrip), topology, metrics, every hfun layer against analytic cases, post-processing pieces on synthetic meshes, server endpoints via httpx TestClient.
- **Fast end-to-end**: coarse global generation (~300 km base, a few thousand nodes, seconds) exercises the whole jigsaw pipeline in CI-speed tests; NG5 is manual perf acceptance only.
- **Frontend**: vitest for pure logic (colormap, id encode/decode, raycast→lon/lat, tangent-drag math). Rendering itself is validated by the spike and per-milestone manual acceptance checklists.
- **e2e**: none initially; introduce a Playwright smoke test (page loads, canvas gets WebGL2 context, HUD shows mesh counts) in Task 18 when Draw-mode interactions appear — from then on treat it with the same must-pass rigor.
- **Golden comparisons**: against **static committed fixtures** captured from a one-time legacy fmesh run (see Task 19 first item) — fmesh needs a py≤3.9 env and is never executed inside fmesh2's test suite.

## Technical Details

**Binary buffer protocol** (spike-validated): per mesh — `pos` (float32×3 unit-sphere xyz, Y=north), `pos2` (float32×3 Plate Carrée, x=lon_rad, y=lat_rad), `tri` (uint32×3), `edge` (uint32×2 unique undirected), `res`/`dep` (float32 per vertex), `meta` JSON (counts, percentile ranges, byte sizes). Dateline: triangles spanning >180° lon get west-side vertices duplicated at +360°; sphere positions of duplicates coincide; scalars copied. Projections beyond Plate Carrée = additional position buffers, morphed in the vertex shader via `mix(positionA, positionB, uMorph)`.

**Hfun composition**: float32 km on regular lat/lon grid; layers applied in order with `min` (default) or `replace`; passed to jigsaw as `ellipsoid-grid` hfun in radians with `hfun_scal="absolute"`. Grid density default: ≥4 cells across the finest transition band; warn otherwise.

**jigsaw options** (fmesh-proven): `mesh_dims=2`, `optm_qlim=0.95`, `optm_iter=32`, `mesh_top1=True`, `geom_feat=True`, ellipsoid radii 6371 km.

**Renumbering guarantee** (M3): outside-region nodes keep exact lon/lat/depth; ids remapped contiguously with exported `old_id,new_id` table so existing FESOM run configs can be migrated.

**Reproducibility definition**: same project + same **cached raw jigsaw mesh** + deterministic postprocess → bit-identical output (tested via `--only-postprocess`). A fresh jigsaw invocation is *not* assumed bit-deterministic across runs/platforms; the raw-mesh cache in the project directory is the determinism anchor. Edit-journal replay (M4) is fully deterministic (pure numpy).

**Performance budgets**: NG5 open <10 s warm / <60 s cold (ASCII parse 16 s measured); buffer fetch localhost ~2 s; 60 fps navigation with wireframe; hfun recompose for live preview <1 s at 0.5° grid (coast layer cached after first compose).

**Key vectorization replacements for fmesh loops**: coastline distance (KDTree vs per-gridpoint polygon scan), region blending (stereographic + shapely distance vs per-gridpoint transforms), land cut (grid sampler vs per-node `gradapproach`), lake removal (`connected_components` vs Python BFS), loose elements (array valence passes vs dict loops).
